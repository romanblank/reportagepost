## Архитектура и запуск локально
- Next.js 16 (App Router, src/, сборка ТОЛЬКО webpack), TypeScript strict, Tailwind CSS 4, Prisma 7 + PostgreSQL, ESLint. Тесты: Vitest (юниты/смоук), Playwright (e2e, добавится в S2).
- Запуск: `docker compose up -d` (PG на 5434; 5433 занят другой платформой оператора) → `npx prisma generate` → `npm run dev`. Миграции: `npx prisma migrate dev`.
- Prisma 7: URL БД в `prisma.config.ts` (не в schema), рантайм через `@prisma/adapter-pg` (`src/lib/db.ts`).
- `npm run build` — прод-сборка; `npm test` — тесты.
- Деплой: Docker-образ на VM Yandex Cloud за nginx (цепочка появится в S0-инфраструктуре).

После изменения schema — `npx prisma generate` (migrate dev не всегда регенерит). Тесты, создающие Notification (отзыв/заявка/подписка/сообщение), в cleanup удаляют notification ДО user (FK RESTRICT). Интеграции (Telegram/email/Vision/SSE) — провайдер за абстракцией, no-op без ключа.
- **Урок enum-расширения (2026-07-15)**: добавление значений в `ModerationStatus` (DRAFT/NEEDS_REVISION) валит `next build` на исчерпывающих мапах `Record<...,...> as const`, индексируемых статусом (STATUS_LABEL в кабинете) — TS «Property 'DRAFT' does not exist». Правило: при добавлении значения enum — сразу grep всех мап/switch по нему и дополнить.

- **🔴 RSC-грабля (2026-07-14): нельзя передавать ФУНКЦИЮ (render-prop `children={(x)=>...}`) из серверного компонента в client-компонент** — рантайм-500 «Functions cannot be passed directly to Client Components». Было в LightboxGallery на профиле/серии (обе страницы 500). Фикс: client-галерея принимает только сериализуемые данные, рендерит сетку сама (PortfolioGallery/StoryGallery + LightboxModal).
- **🔴 НЕ РЕШЕНО: Soft-404 на force-dynamic каталожных роутах (2026-07-16)**: `[country]/[city]` и `[country]/[city]/[category]` с `dynamic='force-dynamic'` при несуществующем городе/категории отдают HTTP **200** + not-found UI (стриминг флашит 200 до notFound). Профиль/серия (не force-dynamic) отдают 404 верно. **Пробовал `notFound()` в generateMetadata — НЕ помогло** (200 остаётся; на force-dynamic стриминг стартует раньше метаданных). Кандидаты на реальный фикс (к S4, сейчас noindex — не горит): (а) middleware-валидация категории (список из 6 фикс.) с rewrite на 404; (б) убрать force-dynamic и решить исходную причину его добавления (searchParams + prerender-без-DATABASE_URL) иначе; (в) generateStaticParams+dynamicParams=false на сегменте [category]. Проверять СТАТУСОМ (`-w %{http_code}`), не разметкой.
- **🔴 Урок верификации: `curl | grep` разметки = НЕДОСТАТОЧНО.** При SSR-стриминге ранний HTML (шапка) флашится ДО ошибки в компоненте ниже — grep находит маркер, а страница всё равно 500. Ложная зелень маскировала битый профиль ~5 деплоев. ПРАВИЛО: проверять HTTP-статус (`-w "%{http_code}"`), а для критичных страниц — локальный прод-сервер (`npm start` + curl, ловить `⨯` в логе) или реальный e2e.

## Уроки CI/деплоя (2026-07-13, первая настройка пайплайна)
- **Лок-файл и платформенные optional deps** (sharp/emnapi/aws-sdk): `npm i <pkg>` на macOS пишет неполный lock → `npm ci` в Linux-CI падает. ПРАВИЛО: после ЛЮБОГО `npm i` сразу `rm -rf node_modules package-lock.json && npm install` (не `--package-lock-only`). Наступали 3 раза (sharp, emnapi, aws-sdk) — gate не ловит, т.к. локальные node_modules полные.
- **Тесты самодостаточны**: интеграционный тест сам создаёт нужные ему записи БД (и убирает за собой). Полагаться на «в моей базе уже есть фотограф» = зелёное локально, красное в CI.
- **Dockerfile**: `ENV NODE_ENV=production` ставить ПОСЛЕ `npm ci` и `npm run build` — иначе npm пропустит dev-зависимости (tailwind/ts), нужные билду.
- **zsh**: `$USERNAME` — зарезервированная переменная (= имя OS-пользователя), не использовать в скриптах проверок.
- **tsx-скрипты**: обязательный `import 'dotenv/config'`; инлайн `tsx -e` с `$` в bash ломается на экранировании — писать временный файл В ПРОЕКТЕ (module resolution от расположения файла).
- **Health обязан проверять зависимости**: /health без SELECT 1 дал «зелёный» деплой при мёртвом TLS к Managed PG (2026-07-13). Managed PG Яндекса требует CA-сертификат (CA.pem в образ + sslmode=verify-full&sslrootcert=…).
- **Билд проверять БЕЗ DATABASE_URL** (prepare-deploy делает `env -u DATABASE_URL`): страница со static/ISR (`revalidate`/дефолт), лезущая в БД, падает на пререндере в Docker-билде, где секретов нет. Локальный `.env` это МАСКИРУЕТ — `npm run build` проходит локально, красный в CI. Правило: страницы с запросами к БД → `export const dynamic = 'force-dynamic'` (случилось с /ru/community 2026-07-14).
- **Прод-данные — только через Actions-workflow** (инвайты, админы): локальные скрипты пишут в ЛОКАЛЬНУЮ базу; с ноутбука прод недоступен (сеть).
- **Серийная очередь деплоев медленная — не паника (2026-07-16)**: `concurrency: deploy-main, cancel-in-progress: false` → пуши деплоятся ПО ОЧЕРЕДИ; N коммитов × Docker-сборка Next.js ≈ N×4 мин (4 коммита долетели за ~16 мин). `/health` показывает только ФИНАЛЬНЫЙ образ — промежуточные SHA проскакивают. Не звать оператора «деплой завис», пока не прошло ≥20 мин застоя `/health`. CI не виден напрямую (PAT 403 на Actions/check-runs) — статус деплоя ТОЛЬКО через poll `/health` version=SHA. Приём диагностики «код или инфра»: одноразовый docker PG на свободном порту + `prisma migrate deploy && db:seed && npm test` (не трогая локальную dev-БД с реальными аккаунтами) воспроизводит CI-тест-джобу на чистой БД.
- **Сид справочников на проде**: Docker гонял только `migrate deploy` → города/категории пусты → анкета падала `city_not_found` (2026-07-14). Сид (`npm run db:seed`, идемпотентный) встроен в CMD после миграций + workflow Seed prod. Урок: любые справочные данные, нужные рантайму, засевать на старте контейнера, не только локально.
